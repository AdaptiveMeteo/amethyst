Requirements
------------------
CovTable2FirstGuessCov has been written for linux. Even if it MIGHT work with other operating systems, it has never been tested nor has been written
for this intent.

Moreover, to be able to run CovTable2FirstGuessCov, you should have the following software installed: 

- Python 2.7 or Python 3.4
- Numpy >= 1.9
- Scipy >= 0.13
- NetCDF4 for python


How to install
------------------
This software do not requires any installation. It you have the CovTable2FirstGuessCov directory in your machine, then you can launch the software.


The Covariance Table
----------------------
The only input file required by this script is a covariance table. A covariance table is a netcdf file with the following structure.
In the root directory of the file there are two arrays called *Latitude* and *Longitude*. They can be monodimensional arrays or matrices and represent
the coordinates for which we have information about the atmospheric covariance.

Inside the root directory, we have two groups: *Associations* and *Profiles*.

In the profiles group, we have several tables: one for each physical variable we want to use inside Mirto and one for the crossed covariances. For example,
if your covariance tables contains the covariances for the temperature (T) and for the water vapour (q), then inside the profiles group you will find a
variable called T and a variable q. Potentially, you could also find a variable called T_q or q_T. You can think at these tables as monodimensional arrays of
matrices. Each matrix is a possible covariance matrix for its physical variable that must be applied in a particular point. The cross variables (like T_q)
contain matrices that are the covariance beween their physical quantities. In our example, the complete covariance matrix for a particular point can be
generated by stacking the matrices in the following way:

.. math::

   \left(\begin{array}[cc] {}T & T\_q \\ (T\_q)^T & q \end{array}\right)

The next point that must be addressed is how the software knows where to apply each covariance matrix. For this reason, there are the association tables.
Inside the Associations group, indeed, there is one table for each physical variable (the same variables that are saved in the Profiles group). The
dimensions of the tables are the same of the Latitude and Longitude tables that are saved in the root directory of the file. These tables associate an
integer to each geographical point. This integer is the number of the profile of the profile table with the same name that must be used for that point. So,
for example, if for a particular point the table T in the Association group report 3 as value, then in that point the covariance table to use for the
temperature will be T[3] where T is the T table of the Profiles group.
